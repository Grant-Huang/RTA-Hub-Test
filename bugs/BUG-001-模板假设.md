# BUG-001: 模板假设被当作用户输入

## 问题概述

| 属性 | 值 |
|------|-----|
| **Bug ID** | BUG-001 |
| **严重程度** | Critical |
| **测试场景** | 场景一：标准 L 型厨房 |
| **测试模式** | 被动式用户 |
| **相关测试日志** | `Scenario-1/conversation.html` |

## 问题描述

用户仅输入 "L-shape"（选择布局类型），但系统将模板中的假设值（Wall North=144", Wall East=120", Ceiling=96" 等）放入 Confirmation Panel，并标记为 "clarify" 状态。这些值会误导用户以为 AI 已从对话中提取了这些信息。

## 复现步骤

1. 打开测试网站 http://rta-hub.inkpath.cc
2. 点击 "New" 创建新对话
3. 点击 "L-shape" 按钮选择 L 型布局
4. 观察 Confirmation Panel 的变化

## 用户实际输入

```
L-shape
```
（仅选择布局类型，未提供任何具体尺寸）

## 系统错误确认的信息

| 确认项 | 系统值 | 问题 |
|--------|--------|------|
| Wall North | 144" | 用户从未提供此尺寸 |
| Wall East | 120" | 用户从未提供此尺寸 |
| Ceiling height | 96" | 用户从未提供此尺寸 |
| Plumbing on East | offset 36", width 24" | 模板假设 |
| Window on North | offset 48", width 36" | 模板假设 |
| Door on East | offset 88", width 32" | 模板假设 |

## AI 行为问题

AI 说:
> "I've got your North wall at 144" and East wall at 120", plus the plumbing and window noted. Thanks for that."

仿佛用户已确认这些信息，但实际上用户只说了 "L-shape" 一个词。

## 预期行为

用户只选择布局类型时，AI 应该：
1. **不要**将模板假设值放入 Confirmation Panel
2. **主动询问**墙长、层高等具体尺寸
3. 可以显示模板作为参考，但需要明确标注为"模板参考值"而非"用户输入"

## 实际行为

直接应用模板假设值，放入 Confirmation Panel 要求用户"确认"。

## 根本原因分析

系统使用了 `floorplan-minimal` 模板，当用户选择布局类型时，自动填充了模板中的标准尺寸。这些值被标记为 "clarify"（待确认）状态，但：
1. 用户不知道这些值是模板假设
2. AI 的回复让用户误以为是他们提供的
3. 用户可能不会仔细检查而直接跳过

## 建议修复方案

1. **分离模板值和用户输入**：模板值不应自动进入 Confirmation Panel
2. **明确标注来源**：所有确认项应明确显示来源（用户输入/模板/账户）
3. **修改 AI 回复**：当用户只提供布局类型时，AI 应主动询问具体尺寸，而不是假设
4. **改进确认流程**：模板值应该以不同颜色/样式标注，提醒用户这是参考值
